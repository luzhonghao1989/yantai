# 小说写作工作台产品与技术设计

本方案对应用户提出的八项需求，计划建设本地优先、可切换小说项目的中文写作桌面应用。核心规则是：当前章节绑定创作阶段，右侧资料和 AI 使用该阶段有效的设定版本，修改正文和设定都可追溯、可撤销。

以下为最初产品设计，包含已落地功能与后续扩展；实际完成状态见 [功能状态](feature-status.md)。默认先支持 Windows 单人本地写作，数据结构为后续其他系统和服务入口保留空间。

## 八项需求与验收

| 需求 | 功能设计 | 验收示例 |
| --- | --- | --- |
| 正文写作与字体调整 | 富文本编辑、全篇显示字体与选区字体、字号、行距、段间距、首行缩进、主题、专注模式、字数统计、查找替换 | 中文输入过程中不被保存或 AI 更新打断；重启后正文和显示偏好保留 |
| 小说分项目并切换 | 项目书架、新建与打开、最近编辑位置、独立项目数据库、复制与导出 | 切换小说不串正文、设定、检索结果或 AI 历史 |
| 大纲细纲故事线 | 全书大纲、卷纲、阶段细纲、章纲、场景节拍；多条故事线与伏笔 | 一章可关联多个故事线节点，查看铺垫、推进、回收状态 |
| 分时期的人物物品场景 | 稳定身份、基础档案、阶段版本、关系历史、变更来源 | 同一人物早期胆怯、后期果断，切回早期章节仍显示早期性格 |
| 按卷或阶段导入并调用 | 卷默认资料集、阶段资料集、章节增减与固定卡片、文件导入 | 切换章节后右侧立即显示相应版本；导入可预览与去重 |
| 本地 AI 与有约束的扩写 | Ollama、LM Studio、兼容服务；上下文构建、流式候选、差异预览、采纳撤销 | 请求中含当前大纲细纲故事线和有效设定；超出预算时明确提示 |
| 文风评价与检测 | 规则检查、AI 审稿、人物与事实一致性、跨章重复、实验性 AI 来源检测 | 问题定位到原文，说明依据；没有调用模型时不伪造 AI 检查结果 |
| AI 搜相关片段找灵感 | 已写正文检索、导入素材检索、联网来源检索、原创场景构思 | 检索返回来源、段落位置和关联原因；搜索与生成内容清晰区分 |

## 写作界面

建议三栏布局：左侧 240 像素左右，中间弹性宽度，右侧 340 像素左右。两侧可拖动、折叠，窄窗口改为抽屉。正文阅读宽度建议 720 至 860 像素，用户可调整。

顶栏显示项目切换、当前卷与阶段、保存状态、全局搜索和导出。左侧组织卷章，并提供大纲、故事线、人物、物品、场景和素材入口。中间显示章节标题、正文与轻量排版工具栏。底部显示字数、目标进度和当前阶段。

右侧分为“本章资料”“AI 助手”“审稿”“灵感”四个标签。本章资料按人物、物品、场景分组，卡片展示版本阶段、关键状态和关联依据；支持固定、展开详情、加入本章。编辑正文时查看卡片无需离开写作页。

视觉建议：背景 #F5F3ED，编辑纸面 #FFFEFA，主色 #28584B，文字 #28332D，辅助文字 #737B73，提示色 #B88746。正文使用本机宋体、思源宋体或用户选择的可用字体；界面使用微软雅黑等清晰的无衬线字体。外部字体缺失时提供回退。

所有管理页使用同一套间距、按钮、卡片与表单。暗色主题保留相同信息层级。专注模式收起目录和右侧，只保留正文、保存状态及必要快捷键。

字体设置要区分“编辑时显示”与“正文内格式”：前者影响阅读体验，后者影响富文本导出。TXT 导出仅保留文字。先支持 TXT、Markdown、完整项目包，随后增加 DOCX、EPUB。

## 项目与数据保存

每本小说保存为独立目录，包含 project.json、novel.db、assets、exports 和 backups。project.json 保存项目稳定 ID、名称、数据格式版本；SQLite 保存正文、结构和设定。应用全局索引只记录项目位置与偏好。

数据库作为正式数据源，TXT 或 Markdown 文件作为导出快照，避免两份可编辑正文互相覆盖。正文保存 Tiptap JSON，同时生成纯文本用于搜索、字数和检查。导出完整项目包时包含数据库与资源，API 密钥不随项目导出。

自动保存需要在中文组合输入结束后执行，保存结果以数据库提交为准。保存中、已保存、失败状态真实可见。章节和设定均使用 revision 防止旧请求覆盖新版本；项目切换先提交待保存内容，失败时保留缓冲并提示。

备份采用 SQLite 一致性备份或受控关闭后的复制，不能随意只复制活动中的 db 文件而漏掉 WAL。保存历史支持章节回退；升级数据库前先备份并执行可验证的迁移。

## 卷阶段章节与故事时间

卷是组织单位，阶段是细纲与设定生效单位。一个卷可以有多个阶段，每章绑定一个阶段。需要倒叙、插叙时，允许章节或场景显式指定故事时间，避免用阅读顺序替代人物年龄与事件顺序。

稳定 ID 标识卷、阶段、章节、场景和设定实体，拖动章节仅修改排序。设定版本绑定阶段或故事时间边界，重排章节不应悄悄改写生效范围。跨阶段搬移章节时预览资料变化，并标记依赖此章的报告和摘要待更新。

第一版使用显式阶段与场景时间覆盖；复杂的多时间线分支在后续扩展，提前保留 scene_id、story_time 和 timeline_id 字段。

## 大纲细纲与故事线

全书大纲记录主题、主冲突、整体走向和结局方向。卷纲记录本卷目标与主要转折。阶段细纲记录阶段目标、起止状态、必须发生和不可发生的事件。章纲与场景节拍进一步描述视角、出场资料、冲突、信息释放和结尾承接。

故事线独立于目录树：一个节点可关联多个章节，一章也可推进多条故事线。节点有计划、已发生、已回收或放弃状态。伏笔另存埋设点、预计回收点、实际回收点和读者已知程度。主线、感情线和悬疑线可以并行查看。

计划事件与正文中已发生事实分别保存。全书大纲可以含未来方向，但生成当前章时必须区分“用于控制方向的未来规划”和“人物已经知道的事实”。

## 人物物品场景的版本

统一分为 Entity 与 EntityVersion。Entity 保存稳定 ID、名称、别名和类型；版本保存适用范围、字段、变更原因和来源章节。

| 类型 | 基础信息 | 随阶段变化的信息 |
| --- | --- | --- |
| 人物 | 身份、背景、核心动机、说话方式 | 年龄、性格表现、喜好、能力、伤势、关系、持有物、已知信息 |
| 物品 | 类别、来历、固有限制 | 所有者、所在位置、完整程度、效果、数量、使用次数 |
| 场景 | 地理位置、结构、相邻地点 | 时间、天气、控制者、破坏程度、可进入条件、在场人物 |

例：同一把剑在入门阶段由师父持有且完好，在历练阶段由主角持有且剑刃缺损。查看入门章节时使用前一个版本。

版本范围应无歧义，同一实体在同一阶段不能同时有两个有效版本。允许明确继承上一有效版本，未设定字段显示为未知，不能由 AI 擅自填成事实。历史设定默认冻结；作者可以修订并记录原因。

正文产生状态变化后，AI 可以生成设定更新提案。作者审核后才成为正式版本。若发现正文与设定冲突，展示冲突两端和来源，不自动决定哪一个正确。

## 分阶段资料调用与导入

资料集记录绑定关系，不复制实体档案。当前章资料由项目常驻资料、卷默认资料、阶段资料和章节显式增减合并，章节级选择优先。实际显示字段由版本解析器按阶段或场景故事时间决定。

区分“仅在右侧查看”和“加入 AI 上下文”。作者可固定高频卡片、临时搜索其他资料，但临时查看不应自动进入模型请求。检索可以推荐相关设定，由作者选择或按明确规则加入。

第一版导入 JSON、CSV、Markdown 和 TXT。导入界面先展示字段映射、实体匹配和冲突；同名人物跨项目不自动合并。新增导入创建记录与来源，不直接覆盖已有历史版本。DOCX 等格式另行增加解析器。

## AI 服务与上下文

Go 定义 Provider 接口，统一连接检测、模型列表、流式输出、取消、错误与用量。首版实现 Ollama 和兼容接口适配，LM Studio 通过兼容接口接入。写作、审稿和向量检索模型可以分别配置。

请求前构建 ContextPackage，包含当前项目、章或场景、目标阶段、正文 revision、设定版本 ID、任务要求和资料引用。资料按照以下优先级组织：

1. 当前任务、选中文本或正文锚点，以及必须遵守的世界规则。
2. 全书大纲摘要、卷纲、当前阶段细纲、章纲或场景节拍。
3. 当前故事线节点、待推进伏笔、承接要求。
4. 当前有效的人物、物品、场景，以及相关人物的已知信息。
5. 前章摘要、最近正文与检索召回的已有事实。
6. 本项目文风要求、作者样文摘要和负面表达规则。

上下文面板展示每项资料、来源、版本、是否纳入和估计 token。给生成输出留出预算，优先删减可选素材或摘要；必须资料超过窗口时阻止发送并提示如何缩小任务，不能静默截断核心设定。中文 token 估算标注误差，有适配的 tokenizer 时使用实际计数。

检索先按项目与阶段筛选，再执行关键词或向量召回。前文事实不能召回尚未发生的未来事实；未来规划单独标记为计划。场景内还需遵守人物知情范围，避免作者知道的秘密自动出现在人物对白中。

生成候选与正文分开，支持续写、扩写、选区改写、对白方案和场景构思。输出通过规则与 AI 一致性检查后供作者预览，仍不能保证绝不偏离。采纳时检查正文 revision，防止流式等待期间的手工修改被覆盖；采纳记录可撤销。

## 文风评价和检测

本地规则检查提供重复词句、标点、段落长度、称谓混用和用户自定义禁用表达。中文断句与字数规则统一定义。长篇重复检测在段落级索引上执行，报告区分必要的情节呼应与可疑重复，避免自动删改。

AI 审稿按语言、对白、节奏、视角、文风一致性、人物行为和设定连续性分别输出报告。每个问题包含章节与段落锚点、原文片段、理由、引用设定和可选改法。报告绑定正文 revision，正文修改后标为过期。

文风基线由作者设定和选定样文共同形成，比较句式、叙事距离、用词、对白和节奏。评分注明评价规则与模型，仅用于修稿；不用主观总分替代问题依据。

AI 来源检测保留独立入口，可接入本地检测器或外部服务。结果显示工具、版本、适用语言、样本长度和置信说明，短文本或未验证的中文场景显示不适用或参考结果。规则触发数不能包装成“AI 率”，模型审稿也不能包装成作者身份鉴定。首版先记录应用内 AI 生成、采纳与后续编辑历史；对外部导入文本标记来源未知。

## 灵感与片段搜索

提供三个检索范围：本项目正文、作者导入素材、联网资料。输入“雨夜追逐”“久别重逢但互相试探”等需求，返回片段、来源、章节或页码、相关理由和加入素材卡入口。

联网检索采用独立 SearchProvider，不依赖聊天模型凭记忆给网址。结果保留真实来源和时间，网页只取必要摘要或短摘录。AI 将检索结果归纳为场景技巧、冲突安排和可原创的方向。没有实际搜索时，仅提供明确标记的原创构思。

素材可以加入灵感板，不能直接当作本小说事实。AI 生成内容和真实检索片段视觉上区分。没有向量模型时回退关键词检索，不影响基本使用。

## 技术结构

建议模块如下：

| 模块 | 职责 |
| --- | --- |
| frontend | React 工作台、Tiptap 编辑器、设置与报告 |
| internal/project | 项目创建打开切换、索引与生命周期 |
| internal/manuscript | 卷章场景、正文、修订、导出 |
| internal/planning | 大纲、细纲、故事线与伏笔 |
| internal/lore | 实体、阶段版本、关系、资料集 |
| internal/context | 阶段解析、知情限制、预算与请求快照 |
| internal/ai | 服务适配、流式、取消、候选与采纳 |
| internal/review | 本地检查、AI 审稿、报告锚点 |
| internal/search | 项目检索、素材索引、联网检索适配 |
| internal/storage | SQLite、事务、迁移、一致性备份 |
| app | Wails 绑定与桌面生命周期 |

主要表包括 volumes、stages、chapters、scenes、outlines、storylines、storyline_nodes、entities、entity_versions、relationships、context_bindings、facts、foreshadowings、revisions、ai_runs、review_reports、sources、source_chunks。项目隔离由独立数据库和请求 project_id 校验共同保障。

## 实施顺序与交付检查

第一阶段交付真正可写的工作台：项目切换、卷章编辑、字体与主题、自动保存、修订回退、基础大纲故事线、人物物品场景的阶段版本与右侧资料、TXT 和项目包导入导出。界面与保存能力一起验收。

第二阶段接入本地与兼容 AI：连接测试、上下文预览、预算处理、流式候选、取消、差异采纳、阶段事实检查。本阶段验收重点是请求资料是否正确以及候选是否覆盖手工编辑。

第三阶段完善文风审稿、跨章重复与一致性、素材库语义检索和联网灵感。AI 来源检测作为实验能力接入，单独验证中文小说适用性。随后增加 DOCX、EPUB 和更复杂的场景时间线。

实现时需要重点验证：中文组合输入、崩溃恢复、保存失败、项目切换期间的未完成任务、历史阶段解析、章节重排、倒叙场景、token 超限、过期候选采纳、备份恢复和导出再导入。候选产品的宣传不能替代这些验证。
