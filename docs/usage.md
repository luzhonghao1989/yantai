# Yantai使用说明

Yantai是本地优先的小说写作桌面应用。启动 build/bin/Yantai.exe，在书架新建小说，或点击体验示例小说。默认数据保存在可执行文件旁的 data 目录，移动软件时请一起保留该目录。

## 写作与项目切换

左侧导航切换正文、大纲、故事线和设定页面，卷章树用于打开与新建章节。正文页可调整显示字体、字号、行距和首行缩进；选区字体与加粗斜体会存入正文格式。TXT 和 Markdown 导出目前使用纯文本，不保留这些格式。

修改后约 800 毫秒触发自动保存，Ctrl + S 可立即保存。保存状态以本地数据库提交为准。返回书架或切换项目之前会保存；失败时保留当前项目，可以从导出菜单保存未提交草稿。关闭时仍有待保存内容，桌面版会提示。

显示字体、主题和字号保存在当前客户端；正文和设定保存在项目数据库。保存历史保留最近 200 次项目快照，界面展示最近 50 次。恢复历史会恢复整个项目，当时的正文、设定、故事线和资料都一起恢复，当前版本仍留在历史中。

## 细纲与阶段设定

在大纲页填写全书大纲、世界规则、文风约定与卷纲，创建阶段并填写细纲。阶段按列表顺序推进。正文页右上角选择本章阶段；倒叙章节也可以明确指定较早阶段。首版暂不支持一章内部多个场景各自绑定故事时间。

人物、物品与场景的基础档案保存不变的信息，阶段版本保存性格、喜好、能力、状态、知情范围等变化。当前阶段没有版本时继承最近的历史版本；未来版本不会提前进入早期章节。首次修改继承字段会新建当前阶段版本。

在大纲页勾选阶段资料集，或在正文右侧调整本章资料。常驻档案自动进入所有章节，但可在当前章排除。右侧显示的勾选资料会加入 AI 上下文。

阶段设定可导入 JSON 数组，格式参考 examples/stage-lore.json。kind 分别为 character、item、location。导入前显示数量与目标阶段，作为新档案加入，不覆盖同名设定。当前不提供 CSV 字段映射。

## 故事线

可建立主线、人物关系线与悬念线，每条线添加多个节点。节点关联章节，并记录待推进、已铺垫、已推进、已回收或已放弃状态。当前章关联的节点会进入 AI 上下文。

## AI 辅助

在模型与设置页选择 Ollama 或兼容接口。Ollama 默认地址为 http://127.0.0.1:11434，LM Studio 可使用 http://127.0.0.1:1234/v1。启动对应服务并载入模型，填写真实模型名，点击测试连接。当前首版不包含模型下载器或推理运行时。

正文页右侧 AI 标签支持续写、扩写、改写、原创构思和审稿。扩写与改写会使用选中段落，未选中时处理整章；续写追加到章尾。生成前可查看实际上下文，包括世界规则、大纲、当前细纲、关联故事线、有效设定、前章提要、正文和文风规则。

token 预算是保守估算。资料超过窗口时阻止发送，不会静默截断核心设定。长章节可以拆分章节或增加模型实际支持的窗口。请将上下文窗口设置为模型真正支持的值。

生成候选先显示在右侧，作者主动采纳才修改正文。正文或相关上下文变化后，旧候选不能直接覆盖，可复制或重新生成。停止按钮会取消请求，未完成候选只能复制。构思与审稿结果不会直接改正文。采纳操作可撤销，历史记录可恢复。

API 和搜索密钥保存在本机 data/settings.json，界面读取时不返回密钥明文，项目导出也不包含密钥。当前本机设置文件未加密；共享软件或备份目录时应移除该文件。

## 文风检查与 AI 检测

本地规则检查可识别自定义表达、重复标点、过长段落和完全重复的章内或跨章段落，报告引用原文与段落位置。它不是语义查重，也不会自动判断人物行为是否合理。AI 审稿会读取设定并给出文风与一致性建议，建议仍需作者判断。

来源检测通过独立检测接口提供。设置页填写接口完整地址与可选密钥，审稿页点击请求来源检测。接口应接收 POST JSON：

```json
{"text":"待检测正文","language":"zh"}
```

服务应返回以下形状，score 为 0 至 1，也可为空：

```json
{"score":null,"label":"参考判断","model":"检测器名称与版本","explanation":"判断依据及限制","language":"zh"}
```

不足 200 字的正文不会请求来源检测。服务分数未在本应用中校准，不能证明作者身份。应用内候选采纳次数只记录操作，不表示当前正文的 AI 占比。

## 素材与灵感

灵感页可导入 TXT 或 Markdown 素材，通过关键词与中文词组检索本书正文和素材，返回段落来源。“AI 帮我找片段”让模型结合当前细纲规划一至三个检索词，再执行真实的本地或联网搜索，并展示实际检索词。可在合并下拉框中选择本地语义检索，使用配置的向量模型。AI 原创构思按照当前故事给出不同方案，明确区别于真实搜索结果。

联网检索默认使用免密钥 Bing RSS；可选配置 Brave Search API 密钥后使用 Brave。返回网页摘要与真实来源，可收藏进素材库。当前不自动抓取完整作品或正文片段。

“文风描写参考”会让当前 AI 模型规划相似桥段检索词，实际联网搜索后，把最多八条网页摘要连同当前章纲、前情提要、阶段细纲、故事线及人物等有效设定交给模型，提供写法分析与原创示例。结果中的 [编号] 对应下方来源。需要配置可用模型，但联网搜索无需必填密钥；参考质量取决于模型与搜索结果。未填写关键词时使用当前章纲。

写作页右侧的“资料”标签提供可展开的“章纲”“前情提要”，直接查看和编辑，自动保存；本章前情提要与符合阶段条件的前章提要都会进入上下文。

## 导出与恢复

导出支持 TXT、Markdown 与完整项目 JSON。JSON 包含正文格式、设定版本、规划、素材和 AI 操作记录，可以导入为独立小说副本；首版 JSON 项目快照不包含外部附件，应用尚不支持封面或图片附件。DOCX 与 EPUB 已支持，可从顶部导出菜单下载。

数据库保存采用事务和版本冲突检查，多个窗口不允许旧版本覆盖新版本。手动备份数据库前请关闭应用并保留整个项目目录，或者直接使用完整项目 JSON 导出。

## 跨电脑备份

在项目顶部点击“备份项目”，选择保存位置，即可生成带时间戳的 JSON 备份。将文件复制到另一台电脑，在Yantai书架点击“导入项目”选择该文件，恢复为独立副本，不覆盖原项目。

备份包括当前正文及字体格式、卷与阶段、大纲与细纲、故事线、人物/物品/场景的全部阶段设定、常用档案字段、资料绑定、参考素材与 AI 候选采纳记录。备份是当前项目快照，不含历史版本、全局模型配置/API 密钥或本机显示字体偏好。原项目不会因备份而改变。

上下文窗口与输出 token 上限均无软件固定最大值，只要求正整数且上下文大于输出。模型支持 262144 token 时，可将上下文设为 `262144`，输出设为 `8192`。填写的值仍需符合模型服务实际能力。

进入模型设置或更改服务地址后，会自动读取模型列表；尚未选择模型时选取列表中的第一项。选择模型后读取服务提供的上下文及输出容量，获取不到时保留手动值，读取期间手动修改的数值也会保留。自动填入后需点击“保存设置”。Ollama 读取 `/api/show` 的模型上下文信息；兼容服务读取 `/models` 返回的容量字段，本机 LM Studio 可使用原生元数据接口。模型声明的最大容量不等同于服务当前已加载的运行窗口。Ollama 请求分别传递 `num_ctx` 与 `num_predict`；兼容接口实际运行窗口仍由服务端配置决定。

接口依据：[Ollama 模型信息](https://docs.ollama.com/api/show)、[LM Studio 元数据接口](https://lmstudio.ai/docs/developer/rest/endpoints)。

## v0.2 故事线

故事线页面左侧显示名称列表和节点数，点击名称后右侧展示并编辑该故事线。新建后自动选中新故事线，重新打开项目会记住上次选择。节点仍支持剧情细节、推进状态及关联章节。旧项目数据无需转换。

大纲与细纲已拆分为两个页面。大纲左侧选择总览或卷，分别编辑全书大纲、世界规则、文风约定与该卷大纲；细纲左侧选择卷纲，右侧查看该卷的细纲阶段，编辑阶段目标、资料集和关联章节章纲。可以从卷纲直接进入本卷细纲，也可以从写作右侧进入当前章节阶段。



## v0.3 使用调整

章纲、前情提要只显示在资料栏，AI 栏专注写作任务。灵感页和右侧灵感栏通过“灵感方式”下拉选择关键词检索、AI 帮我找片段或文风描写参考，再点击检索或生成参考；文风参考固定联网搜索。

审稿中的“错别字检查”无需模型或密钥，优先显示本地常见词语错写及重复标点，提供所在段落和建议修改。规则库覆盖有限，结果为疑似错误，需结合语境确认，不自动替换。人物名等单字不进行任意推断。长段落、章内/跨章重复、自定义文风规则保留在折叠的“其他写作检查”。


v0.3 灵感界面补充调整：灵感页与写作右侧灵感栏移除原创构思入口。检索方式和范围合并为一个下拉框，可选本地素材检索、联网关键词检索、AI 帮我找片段（本地/联网）、文风描写参考（联网）。


写作底栏同时显示原有字数（不含空白，含标点）和纯字数。纯字数只统计 Unicode 字母与数字（包括汉字），不计空白、标点和符号，随输入、删除、撤销以及章节切换更新。


## v0.4 写作流程补齐

- 查找替换：工具栏搜索按钮或 Ctrl+H，精确匹配当前章文字，可逐处定位、替换或全部替换。全部替换是一笔编辑，可一次撤销；替换词为空时删除匹配内容。
- 最近编辑位置：当前电脑按项目和章节记住光标与滚动位置，回到该章后恢复。正文缩短时自动限制到合法位置。
- CSV/JSON 设定导入：细纲页“导入 JSON / CSV 设定到此阶段”，先预览记录并查看同名数量。常用字段自动匹配，也可展开“字段映射”调整。默认跳过已有及本批内同名同类型记录，可改为新建独立档案；不覆盖既有档案。CSV 支持带引号的逗号、换行和双引号，一次最多 200 条。
- DOCX/EPUB：顶部导出菜单新增 Word 文档与电子书。保留标题、段落、加粗、斜体等基本格式，DOCX 保留选区字体；EPUB 包含可跳转的章节目录，显示字体由阅读器决定。桌面二进制导出使用独立保存方法，不经过文本转换。
- AI 改写对比：扩写/改写候选显示段落对比，红色是删除、绿色是新增，不自动改变正文；超过 250 行时改用并排预览，避免大段 diff 影响界面响应。
- 语义检索：设置页填写“向量模型”，与写作模型可以不同，但使用同一服务地址。模型必须支持 Ollama `/api/embed` 或兼容 `/embeddings`，未配置时继续使用普通关键词检索。灵感下拉选择“本地语义检索”，按含义返回实际正文/素材，分数为向量余弦相似度，不是正确率。正文只检索当前章及之前且阶段不晚于当前章的内容；作者导入素材作为参考。首次检索会计算向量，后续同内容在当前进程内复用；修改正文不会返回被删掉的旧段落，重启后会重建。向量计算由设置中的模型服务执行，素材数据仍存放在本机。

CSV 示例：

```csv
名称,类型,基础设定,性别,出生地,当前状态
林晚,人物,小镇少女,女,青石镇,尚未修炼
铜铃,物品,辨识山雾的器物,,,林晚持有
旧渡口,场景,河边木栈桥,,,雨后
```

正文工具栏新增「去除空白行」：清理当前章节的空段落、仅空格行及软换行中的空行；保留非空文本格式，可按 Ctrl+Z 撤销。大纲的总览区以「全书总览 / 世界规则 / 文风约定」标签分别编辑，每次显示一项并扩大正文区域。

正文修改标记：选中需要修改的文字，点击工具栏「修改标记」，再点「标记选中文字」并填写说明。正文显示黄色高亮，点击高亮或列表原文可定位。处理完可标为已处理，也可重新待修改、移除标记；操作支持撤销。标记随正文移动，全部删除被标文字时相应标记也消失。标记保存在项目 JSON 备份中；TXT/Markdown/DOCX/EPUB 正文导出不包含内部修改说明。

按标记修改：在右侧「AI」的「写作任务」选择「按标记修改 · 依据修改意见」，勾选本章待修改标记，点击「开始按标记修改」。勾选的标记必须填写意见；已处理标记不参与。模型同时读取章纲、阶段细纲、故事线、有效设定及文风要求，结果按标记展示原文与改文。确认后点击「采纳候选」，只替换勾选范围并标为已处理，支持一次撤销恢复全部原文和标记。生成后正文、意见或设定变化时需重新生成；模型返回不完整或错误的标记结果时不会写入正文。

若模型原样返回部分或全部标记，软件自动重试一次（会额外调用一次模型，可点击停止）。仍未改动的位置显示提示；全部未改动时禁止采纳，只有部分改动时「采纳实际修改」只处理有变化的部分，其余标记保持待修改。仅调整空白不算实际修改。内容有变化不代表修改质量已达标，采纳前仍应对照意见查看改文。

AI 审稿结果保存：完成后立即写入项目，AI 栏的「本章审稿与地图历史」及审稿栏的「已保存的 AI 审稿」都可按生成时间重新查看；旧版本已保存在 aiRuns 中的审稿结果也会显示。新结果保留所审正文快照，正文变化后提示基于旧稿；项目 JSON 备份与导入会携带历史。

审稿逐段替换：新 AI 审稿会提供总结以及「完整原段落 / 建议改文 / 修改理由」。满意某条建议时点击该条「替换原文」，只替换对应段落，其余建议保留；每次替换可单独撤销。生成结果和审稿历史中都能操作。旧审稿只有意见时，点击「按审稿意见生成修改段落」，AI 会根据原意见与当前正文生成可替换改文。原文需与当前文档中唯一一个完整段落逐字一致；原文变化、引用不完整、出现多个相同段落或改文无实际变化时，禁止自动替换。

按标记修改的结果中，每处标记也有「替换原文」按钮，可逐处采纳。替换后该标记标为已处理，其他候选继续保留；也可点击底部「采纳实际修改」处理剩余建议。撤销或重做后按钮状态随文稿恢复；若作者另行改动正文或设定，需要重新生成后再替换。

来源检测未配置时显示「配置来源检测服务」，直接进入模型与设置。填写完整检测接口地址及可选密钥并保存后，按钮恢复「请求来源检测」。聊天模型地址不是检测接口；独立服务未配置不影响 AI 审稿或本地错字检查。

场景平面图（SVG）：在 AI 的写作任务选择「场景平面图（SVG）」，选择本章绑定的场景，说明房间/道路/地点需求后生成。使用现有聊天模型及当前阶段场景资料，无需额外图像模型。位置是示意、不代表实测比例；未知的连接使用虚线。支持放大/缩放、SVG 导出和项目内历史保存。不会自动改正文或场景档案。若模型未按 JSON 地图格式返回，会显示格式错误，可调整说明重新生成。

## Yantai v0.4.2 图片管理

左侧「图片」可导入地图、人物、场景及其他参考图，支持分类、预览、名称、备注、原图导出与移除。支持 PNG、JPEG、GIF 和静态 SVG；单张最多 8 MiB、每个项目最多 200 张及总计 32 MiB。动态 SVG、脚本和外链资源不导入。

AI 新生成且格式正确的 SVG 地图自动进入图片栏；以前保存的地图可在 AI 历史中点击「保存到图片」，同一生成记录不会重复添加。图片原文件保存在数据目录的 images 中，项目及历史只记录引用；移除后仍可从历史恢复。完整 JSON 备份会包含实际图片数据，另一台电脑导入时自动恢复文件；DOCX/EPUB 文稿导出暂不插入参考图片。

桌面文件统一为 Yantai.exe，浏览器程序为 Yantai-browser.exe。继续使用原来的 data 目录即可读取旧项目；新的数据目录变量是 YANTAI_DATA，旧变量仍兼容。修改程序文件名不会自动更名用户创建的小说名称。

## 场景绘制（ComfyUI）

在「模型与设置 → 图片生成（ComfyUI）」填写服务地址，例如 `http://192.168.0.234:19897`。可选择内置 Flux3 或 Qwen2.1 文生图方案，再点击「保存并测试 ComfyUI」。两个预置参考 workflow 目录的 331 Flux3 文生图与 324 Qwen2.1 文生图，已展开子图，并使用普通 PNG SaveImage 输出；模型文件需存在于对应服务。

也可导入 ComfyUI「导出 API」得到的 JSON，选择正向提示词字段、可选负向字段和图片输出节点。画布格式 JSON（含 nodes、links、子图）请先在 ComfyUI 打开并导出 API。设置中的 JSON 可调整模型、LoRA、尺寸、批量及采样参数；不会自动安装模型或自定义节点。

写作时在 AI 的写作任务中选择「场景绘制（ComfyUI）」，点击「根据本章生成场景图」即可：先保存最新正文，再由设置中的 AI 文字模型读取本章完整正文、章纲、细纲、故事线、人物/场景/物品的当前阶段设定，自动选景并编写画面提示词，然后自动提交 ComfyUI 绘制，完成后保存图片。无需手写正负向提示词；需同时配置可用的文字模型与 ComfyUI。

默认由 AI 自动选择本章一个代表性场景，也可指定本章有效场景，并填写可选的「补充画面要求」（如俯视、夜景或水彩风格）。生成过程中显示 AI 分析、ComfyUI 绘制、保存图片三个阶段；「查看 AI 生成的提示词」可展开核对选景依据及实际正负向提示词。正文或设定在 AI 分析期间改变时，不继续提交旧提示词，需重新生成。种子留空会随机设置工作流内的 seed/noise_seed 数值字段，也可填写固定种子复现。

成功后显示图片预览，并自动保存到项目图片栏，可选择地图、人物、场景、其他分类。图片随完整项目备份携带；原文和档案不会被改写。访问密钥仅用于配置服务的 Bearer 认证网关，保存在本机设置中，不随小说导出。

「停止」在 AI 分析阶段会取消文字模型请求；在 ComfyUI 提交之后只停止本软件等待，不会中断 ComfyUI 上其他任务，已提交任务仍可在 ComfyUI 查看。单次最多接收 8 张 PNG/JPEG/GIF，单张最多 8 MiB，仍受项目 200 张/32 MiB 容量限制。保存失败时保留当前预览并提供重试保存；离开页面前请确认已保存。

审稿改文校验：AI 原样返回或仅改空白时，自动附上原段落与修改意见重试一次。仍无变化的建议显示「未实际修改」，禁止替换，不再误显示「已替换」。历史结果也使用相同校验。

AI 原文定位：审稿建议、审稿历史、按标记修改以及扩写/改写对比提供「定位原文」。对比中的删除/保留原文、标记选择列表，以及普通 AI 回答中与当前正文匹配的引号、行内引用和整段原文可点击定位；引用块提供定位按钮。AI 上下文预览中的当前正文与选中文本也可定位。点击后正文滚动并选中对应文字，不修改内容；重复文字再次点击可切换下一处。定位按当前正文重新查找，修改标记使用标记 ID；原文已变化或替换时提示找不到，不使用旧坐标跳转。

AI 生成进度：正文页的 AI 文字任务在生成期间显示已用时间、模型思考与正式输出阶段；模型返回思考文本时可展开/折叠查看，并自动跟随最新内容，手动向上滚动后暂停跟随。思考仅在本次等待期间显示，完成、停止或失败后清除，不进入候选、复制内容、审稿历史或项目备份。没有提供思考流的模型显示等待时间及正式输出状态；软件不编造思考内容。兼容 Ollama message.thinking、兼容接口 reasoning_content/reasoning/thinking 文本字段及 content 中分片的 think/thinking 标签。

草稿恢复缓存：完整项目草稿保存到 IndexedDB，避免正文、AI 历史和图片占满 localStorage。旧版 localStorage 草稿仍可恢复，在新缓存成功写入或数据库保存成功后清理当前项目的旧缓存。缓存写入与清理失败不会改变数据库保存结果；缓存不可用时提示一次，并应留意顶部保存状态。光标、滚动、字体和主题属于尽力保存的小设置，不会因存储配额不足中断编辑。

审稿一键替换：结构化审稿结果顶部提供「一键替换全部建议」，显示当前可替换段落数。先按当前正文核对所有原段落，再以一笔编辑替换有效改文；原文变化、已替换、无实际修改、找不到唯一原段落，以及同一原段落出现多条冲突建议时跳过并提示数量。当前结果和历史审稿均可使用，部分已逐段替换后可继续替换剩余内容，整批修改可一次撤销。

服务端同步：在“模型与设置”中的服务端同步卡片或书架顶部“服务端同步”填写地址与访问密钥，保存后可立即同步，也可启用按分钟定时同步；定时器只在客户端运行期间执行。同步所有项目当前资料及图片，模型密钥等本机配置保持独立。双端同时改动时在卡片中选择方向，覆盖前在目标端保留同步前历史。部署和冲突规则详见 server-sync.md。
