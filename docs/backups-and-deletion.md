# 每日备份、同步删除与项目范围

客户端和服务端内网工作台的设置中均提供“每日备份”。两端独立配置，默认启用，保留 30 天；备份全部已保存项目，不受同步勾选范围影响。备份程序启动时检查当天是否已有完整备份，此后每小时检查，跨日后自动执行。程序关闭期间无法备份，下一次运行时补做当天备份，不会伪造过去日期的快照。

“立即备份”可随时执行。每份备份保存在数据目录的 `daily-backups/<备份ID>/`，包含项目 JSON、嵌入图片及清单，正文富文本、批注、设定、AI 审稿等项目数据一同保留，不包含模型密钥和同步凭据。日常备份保存当时项目状态，不是每次编辑的完整数据库历史。部分项目读取失败时会显示失败记录，保留已成功备份的项目，并且不清理过期备份；只有新备份完整成功后，才按保留天数清理旧的成功备份。

在“备份记录与恢复”中展开日期，选择小说并确认“恢复为新项目”。恢复始终创建新 ID，不覆盖现有项目，也不会复用已删除的同步身份。恢复后到书架打开核对。选择“仅同步勾选项目”时，需要将恢复的新项目加入同步范围。

服务端书架提供“删除服务端项目”。删除前强制保存该项目的独立备份，即便关闭每日备份也会执行；备份失败则不删除。随后在 `deleted-projects/` 保存永久删除记录，移走项目数据库。删除记录不随 30 天备份过期而清理，旧客户端即使再次上传该 ID，服务端也会拒绝。

客户端同步收到删除记录后：

- 本机与上次同步状态一致：移入本机 `deleted-project-backups/`，从书架移除。
- 本机有未同步修改，或没有同步基线：阻止上传，显示“保留为独立项目”和“确认删除旧副本”。独立副本使用新 ID，原目录仍保留。
- 本窗口在同步期间又产生编辑：保留窗口稿件并提示导出，不用删除通知覆盖尚未保存的文字。

客户端将旧项目移入回收目录前，也会创建可在设置的备份记录中恢复的项目快照。

数据库回收目录 `deleted-project-backups/` 与原有 `local-project-backups/` 独立于每日 JSON 备份，保留数据库及 WAL/历史用于故障恢复，不参与每日备份的过期清理。

同步设置默认“全部项目”。选择“仅同步勾选项目”后，列表合并本机与已保存连接对应的服务端项目，支持新电脑只下载指定小说。先保存地址与凭据，再刷新列表获取远端小说；勾选变更需保存后生效。空选表示不处理任何项目，手动同步和定时同步使用同一范围。未选中项目不上传、不下载、不处理删除通知。服务端自身不主动向客户端发起同步。

需要同时更新客户端和服务端程序。服务端的备份管理、恢复和删除入口只位于经过身份验证的内网 HTTP 工作台；公网 TLS 同步端口继续只开放同步协议，不提供这些管理页面或接口。手动移除服务端磁盘目录不会生成删除记录，应使用工作台的删除按钮。
